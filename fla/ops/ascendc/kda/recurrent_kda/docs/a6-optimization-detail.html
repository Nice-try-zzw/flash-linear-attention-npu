RecurrentKda：A6（ascend960dt）详细设计

基线：PR #997 的 A5 新实现（静态 UB + 资源 Mutex + 逐 token VF）；本文说明 A6 在此基础上按 384KB UB 与三发射做的调整，并可视化 UB 切分变化。

一句话结论 A6 与 A5 是同一套算法，差别只在架构常量：State bank 3→4、窗口 8→32（FP32 K-first 仍为 16）、 Mutex 12→14；UB 占用从约 88% 提升到 93%。三发射不需要新增代码，靠现有“4 行 × 2 段”的 8 条独立短指令流吃满。
相对 PR 的 A5 除了上面的架构常量，A5/A6 的 V=256 legacy 路径还额外做了两件事：删掉 K≠128 的死分支、把 norm/gate/类型转换等全部计算从 UB 级（membase）改为 RegBase（见第 6 节）。

1. 先看 A5：一条序列是怎么算完的

A5 的 V=128 路径把「一条序列 × 一个 value head」当成一个任务，任务再按固定窗口切 tile， tile 内逐个 token 递推状态。整个过程不经过 TPipe/TQue，UB 地址全部是编译期常量。

逐 token 的四步递推

  • S = S * α（gate 衰减，α 来自 gate/beta）
  • dot = S @ k，delta = (v - dot) * β
  • S = S + delta ⊗ k（外积更新）
  • out = S @ q（用更新后的状态）

K=V=128 时每行 128 个 float，一次处理 64 lane，因此每行分两段。

UB 里同时存在的东西

  • State bank：完整 128×128 FP32 状态（64KiB/份），按 bank 轮转
  • 输入双槽：q/k/v/gate/beta 各两套，供 MTE2 提前搬下一 tile
  • out 双槽：tile 内攒齐后一次性搬出
  • 参数双槽：A_log + dt_bias，按 head 预取
  • guard：2048B，含 512B VF 数值 scratch

同步方式（Mutex，而不是 SetFlag/WaitFlag）

每个共享资源配一份 Mutex：State 访问、State 快照、输入槽、参数槽、out 槽。生产者搬完就 Unlock，消费者用前 Lock；Scalar 提交解锁不等于数据已完成，跨流水依赖由 Mutex 排队，同流水内的访存依赖仍用 LocalMemBar/PipeBarrier。

A5 的配置：窗口 X=8、State bank 3 份、Mutex 12 份、可用 UB 按 248KB 计。

2. A6 的两个硬件增量，以及对应改动

增量一：vector 三发射

A5 每拍可发 1 长 + 1 短；A6 可发 1 长 + 2 短。代码里每个 4 行块天然有 4 行 × 每行 2 段 = 8 条互不依赖的短指令流，已经够填满 2 个短槽，所以这部分没有新增代码， 只需要编译器把 8 条流交错排布。

增量二：UB 248KB → 384KB

用多出来的空间做两件事：

  • State bank 3 → 4：逐 token 落盘（ssm_state_indices）时可多留一份快照在飞；
  • 窗口 8 → 32（BF16 / FP32 V-first）：每个 tile 的 DMA/同步/循环开销摊薄一半。
  • FP32 K-first 因 bank 带 32B 行间距（128×136），4 bank 下窗口保持 16，避免 UB 顶死。

每 token 的双槽占用 = q/k/v 3×512 + gate 1024 + beta 64 + out 512 = 3136 B；窗口翻倍只放大这一项，State bank 与固定项不变。

为什么 FP32 K-first 不把窗口也放到 32？ 它的 bank 需要 32B 行间距（128×136），4 bank 共多出 16KB；若窗口取 32，总量变成 382,016 B（97.2%），只剩 11,200B 余量，平台再保留一点 UB 就会 tiling 失败。因此该布局固定 X=16。

4. 三发射：A6 到底多做了什么

三发射不是“多写一条指令”，而是同一拍里能放 1 条长指令 + 2 条短指令。 一个 4 行块里的指令构成是固定的：短指令约 40 条（载入、decay、乘加、outer、S@q）， 长指令 8 条（4 次 S@k 归约 + 4 次 S@q 归约；gate/sigmoid 路径还会多出 Exp/Ln/Div）。 关键条件是这些短指令必须来自不同行——代码里的“4 行 × 每行 2 段”正好给出 8 条独立短流。

A6 三发射

按“块时间”归一化：A5 短槽 40 拍是瓶颈（长槽只占 8 拍）；A6 短槽 20 拍、长槽 8 拍，块时间由短槽主导降到约 20 拍。 这只是上限，真实收益取决于编译器能否把 8 条短流交错到 2 个短槽里，需要用 profiler 看 ReduceSum 占比与短指令双发率。

5. 理论收益与代价

稳态 token：不变

每 token 的 state 读/写（BF16 32+32KiB，FP32 64+64KiB）与 128 行向量指令不会因为 UB 变大或窗口变大而减少。

tile 固定开销：约减半

每 tile 有 5 条输入 DMA、1 条 out DMA、4 次 Mutex 操作和若干标量分支，约 1.0–1.5K 拍。 窗口 16→32 后 tile 数减半，固定开销占比从 6–9% 降到 3–4.5%，长序列约回收 3–4%。

落盘路径：多一份快照

有 ssm_state_indices 时 MTE3 每 token 写一份状态快照；第 4 个 bank 让在飞快照从 2 份变成 3 份， 减少“旧快照未回写就复用 bank”的等待。

6. V=256 legacy：相对 PR 的 A5 还改了什么

V=256 在 A5/A6 上走 legacy（tiling key = 0，每段长度 ≤ 8）。PR 的 A5 里这条路径仍是 TPipe + UB 级 API； 本仓把它换成了纯 RegBase 计算，并删除了不可能进入的分支——aclnn 与 host 已双重保证 K=128、V∈{128,256}。

删掉的死分支

  • InitLocalBuffers：不再另开 broadTmp，直接复用 state 工作区
  • ReduceSumDispatch：固定 ReduceSum128
  • Compute：删除 MatVecMul → ReduceSum → Sub/Muls → ProcessKQ 的 membase 回退
  • CopyInBeta / ProcessHead：删除 alignK_ != 128 的条件同步与 beta 预读

为什么收益集中在“输入准备”

  • legacy 一段最多 8 个 token，每 tile 的固定开销占比高
  • 原实现每行 norm 都要 ReduceSum → GetValue：8 行 × q/k = 16 次 V→S 往返
  • gate 变换原本是 ~7 趟整块 UB 运算 + 7 次 barrier

  • 编译：build.sh --pkg --soc=ascend960dt --ops=recurrent_kda，确认四个 KERNEL_MODE 实例产出。
  • 日志：BF16 / FP32-V-first 为 windowSize=32、ubRestBytes=365632； FP32 K-first 为 windowSize=16、ubRestBytes=331840；stateOutBufferNum=4。
  • 功能：atk_recurrent_kda_a6.json（130 条，S=1…1024，含 31/32/33 窗口边界、空段、padding、slot 索引）。
